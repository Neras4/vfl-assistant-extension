# VFL Assistant v0.5.10

## Изменения в v0.5.10

- Native позиции сохранены; GK/XX/DF/MD/FW/R/L/C имеют понятные русские подписи. Точные позиции остаются компактными.
- Шесть независимых checkbox позволяют выбрать несколько стилей. Без выбора все `plr_style_1..6=0`; повторяющиеся ID нормализуются, значения вне integer 1..6 отклоняются.
- Внутренний фильтр — `styles: [4, 5]`. Экспорт `search.filters.styles` — `[{id: 4, label: "Тики-така"}, {id: 5, label: "Катеначчо"}]`; без выбора — `[]`. Одиночное поле `filters.style` удалено; свойство `players[].style` не меняется.
- Поиск использует сегодняшние торги: значение читается из актуального `select[name="day"]`, из единственного пункта «сегодня, …». Номер дня не хардкодится; если пункт отсутствует, неоднозначен или имеет некорректное значение, поиск останавливается с понятной ошибкой. `day=-3` для поиска рынка не используется.
- На открытой странице рынка форма переиспользуется: 1 поисковый GET, либо 2 при многостраничном результате для сортировки. При старте с другой страницы требуется ещё один GET `transferlist.php` для получения актуальной формы; дополнительных запросов к игрокам нет. Отдельного выбора даты и кеширования нет.
- Сортировки, market row parser, read-only «Мои заявки», Deep, Management и clubData сохранены. `node regression.test.cjs` — PASS.
- Live 04.10.2026 подтверждены native пункт «сегодня» и GET-поиск с двумя стилями: получено 6 игроков на сегодняшний день. Полный запуск установленной панели расширения в cloud browser не проверен: расширение там отсутствует.

## Трансферный рынок (базовая реализация v0.5.9)
- Отдельный компактный раскрываемый блок с кнопками «Найти игроков» и «Мои заявки». При сборе команды рынок не запускается; Training/Scouting/Fitness и clubData.deals не меняются.
- Поиск: позиция pz1 (17 native значений), возраст, цена **в тысячах всоликов**, сила, один или несколько из шести стилей, процент от номинала. Пустые границы отправляются пустыми, как реальная форма VFL: нормализацию выполняет сайт. Служебные defaults явно записаны в коде по проверенной форме и не экспортируются в filters.
- Четыре native сортировки подтверждены live 03.10.2026: strength=5 (сильнейшие), price=7 (дорогие), specials=13 (native порядок спецвозможностей), age=3 (молодые). Первое чтение использует обычный native порядок рынка по цене; выбранная сортировка применяется вторым запросом только при totalPages > 1. Для одной страницы и пустого результата — один поисковый запрос, sort.applied=false (получение формы при старте вне рынка описано выше). Всегда только page=1, до 50 строк; нет обхода страниц и запросов player.php/player_stats/player_contracts.
- Отдельный JSON: `management.transferMarket.search` содержит filters, sort.requested/applied/nativeSort, pagination (totalResults/totalPages/page/pageSize/shownFrom/shownTo) и players. В каждой строке сохраняются ID, доступные ссылки, все перечисленные summary-поля, понятные tooltip-статусы и raw значения. `playerUrl=null`, если в строке есть только ссылка заказа. Денежные значения строк переводятся из «к» в всолики; filters.price остаётся в native тысячах.
- Growth/decline сохраняют percent или min/max и raw из явного title. CSS-звёзды не декодируются по догадке; level/maxLevel заполняются только при текстовых ★/☆. Частично известный стиль сохраняет possibleStyles, однозначный — id/label; «?» и неизвестные числа остаются null/raw. Значение «Нет заявок» с прочерком означает 0. FormTrend читается из title, без sprite mapping.
- «Мои заявки»: один GET `transferlist.php?status=2&day=-3`, отдельный `management.transferMarket.myBids`. Сохраняются текущие purchaseLimits, summary строк, auction, прямые bidPrice/bidPercent и bidRaw. Сумма input ставки в native тысячах переводится в всолики. Статус winning/outbid не угадывается. Нет POST, редактирования заявок, лимитов или каких-либо action-запросов.
- Подтверждены live форма, четыре сортировки, поиск из 47 строк, многостраничный результат из 180 строк, пустой ответ и текущие заявки. Минимальные очищенные фрагменты реальной строки рынка/заявки проверены локально и не опубликованы. Public tests полностью synthetic; старые проверки остаются зелёными. Полный запуск кнопок установленного расширения в cloud browser не проверен: расширение там отсутствует.

## Главное
Стартовая страница: `https://vfliga.com/managerzone.php`

Сбор команды:
- **Собрать мою команду**
- **Собрать ближайшего соперника**

Настройки:
- количество последних матчей;
- глубина сбора:
  - **Обычный** — базовая страница команды/соперника + N матчей;
  - **Глубокий** — профили и последние N матчей игроков; для своей команды также статистика сезона и контракты.

## Что изменилось по сравнению с v0.4
- Экспорт стал компактнее.
- Полный `bodyText` и полный набор всех таблиц больше не сохраняются.
- Сохраняются:
  - core команды;
  - компактный roster;
  - последние N матчей;
  - при deep scan — компактные данные по игрокам.
- `script`, `style`, `noscript`, чат и панель расширения удаляются до анализа.
- Сбор таблиц теперь идёт из очищенного DOM, поэтому `ws_token` не должен попадать в JSON.

## Deep scan в v0.5.7
- Своя команда: `player.php`, найденные вкладки `player_stats.php` и `player_contracts.php` — обычно три запроса на игрока.
- Соперник: только `player.php` — один запрос на игрока. В `playerDetails` отсутствуют `stats` и `contract`.
- `info.recentMatches`: текущий показанный сезон, самые свежие N строк таблицы «Об игроке». Тот же N ограничивает последние матчи команды. Поля: date, competition, opponent, opponentId, homeAway, score, position, minutes, rating, goals, assists, yellowCards, redCards, playerStrength, matchUrl. Скамейка и неизвестные значения сохраняются как null; пропущенные голы вратаря не становятся забитыми.
- Верхние поля игрока берутся из roster, включая неизвестные fatigue/form. `selectedStats` остаётся отдельно от полной статистики.
- Контракт теперь разделён на `current`, `renewal` и `history`. Вместо прежних плоских полей: `current.salaryPerTour`, `renewal.requestedSalaryPerTour` и `renewal.availableTerm`. Renewal содержит прямой запрос зарплаты, отдельный adjustmentPercent и factors с label/percent. Проценты сохраняют знак; зарплата не рассчитывается. BaseSalaryNextSeason отсутствующий на странице экспортируется как null.
- History содержит только реальные строки страницы; дата окончания current берётся из совпавшей строки подписания, если она есть. Полная карьера и дополнительные страницы матчей не обходятся.
- Normal, данные клуба и `team.resources` не менялись: resources отсутствует.

## Установка
1. Распаковать ZIP.
2. Открыть `chrome://extensions` (или страницу расширений браузера).
3. Включить режим разработчика.
4. `Load unpacked / Загрузить распакованное расширение`.
5. Выбрать папку `vfl-assistant-extension-v0.5.10`.
6. Открыть `https://vfliga.com/managerzone.php`.

## Данные клуба в v0.5.6
- Один выключенный по умолчанию чекбокс «Данные клуба»: финансы, история сделок и командная статистика. Только для кнопки своей команды, независимо от normal/deep; deep по-прежнему добавляет только playerDetails.
- Own export всегда содержит `clubDataIncluded: true/false`. При true добавляются отдельные `finances`, `deals`, `teamStatistics`. В opponent export этих полей нет даже при включённом чекбоксе.
- Источники: managerzone `pm=6`, `pm=4`, `pm=3`. Проверяется ID активной команды на каждой странице. Ошибка загрузки или смена команды прерывает сбор, чтобы не экспортировать смешанные данные.
- `finances`: выбранный сезон и ledger `date`, `description`, `balanceBefore`, `income`, `expense`, `balanceAfter`; отсутствующие суммы — null, расход хранится положительным числом. Категория не угадывается, текущий баланс не дублируется. Относительные даты сохраняются как показаны на странице.
- `deals`: выбранный сезон и завершённые transactions с типом, исходным разделом, датой, игроком, суммой и контрагентом. Подтверждены разделы покупок и продаж на трансферном рынке; неудачные попытки и выпускники спортшколы исключены. Блоки аренды/обмена на проверенной странице не представлены, их mapping не угадывается. Суммы с «к» переводятся в единицы игровой валюты. Неподтверждённая структура блока не парсится по предположению.
- `teamStatistics.metrics`: аналитические значения и рейтинги league/continent/country/division; знак изменения читается из title. Для Vs/s11/s14/s17, вместимости и финансов сохраняются только Ranking-поля. Core не перезаписывается. История тренеров не собирается.
- Данные относятся к показанному сезону/страницам. Архивы и все sort-фильтры не обходятся. Новых зависимостей и management collectors нет.
- `team.resources` удалён: уведомления не отражают остаток ресурсов при занятых слотах.
- Проверены DOM и контрольные значения трёх реальных клубных страниц, а также synthetic tests всех комбинаций own/opponent и normal/deep. Полная проверка кнопок и скачанных JSON в установленном расширении остаётся незавершённой: в доступной браузерной сессии расширение отсутствует.

## Management в v0.5.8
- Отдельный выключенный чекбокс «Менеджмент команды», только для своей команды. Независим от Normal/Deep и «Данных клуба».
- Own export всегда содержит `managementIncluded`. При true добавляется отдельный `management: { training, scouting, fitness }`. Opponent полностью игнорирует Management; management-полей и запросов у него нет.
- Ровно шесть запросов: текущая страница и история каждого центра. Нет запросов на каждого игрока, разведки соперника и обхода прошлых сезонов. History тренировок запрашивается с `a=currentSeason&b=currentSeason`, скаутинга — с `season=currentSeason`; выбранный сезон и команда проверяются. При смене команды/сезона сбор прерывается.
- Training: уровень, скорость, слоты, остатки/лимиты, цены, активные тренировки и текущая сезонная история. Если скорость или цена силы — диапазон, обе границы сохраняются (`speedPercentRange`, `strengthMin`/`strengthMax`), одиночное значение остаётся null. Active сохраняет ID/имя, days, progressPercent, cost и подтверждённый строковый target в result. Numeric training codes не декодируются: trainingType остаётся null. History сохраняет season/day/date/result/cost, без повторного roster.
- Scouting: уровень, скорость, цена и пять пар remaining/total с профильной страницы; active дополняется данными таблицы «На изучении». Значения «Сейчас/Будет» сохраняются только как читаемый текст или короткий поясняющий title, без реконструкции иконок. Completed содержит реальные строки «Завершено изучений» выбранного сезона; «3 из 4» сохраняется как level/maxLevel/raw.
- Fitness: параметры центра и planned/completed/cancelled по явным заголовкам. oldForm/newForm — `{ percent, trend }` из title, без числовых кодов цветов. День и дата сохраняются как показаны VFL.
- **Ограничение истории Fitness:** у `page=2` нет селектора сезона. Для прошлых событий без явно подтверждённого сезона строки исключаются и появляется `scopeWarnings`; строки явно другого сезона также исключаются. Текущие запланированные изменения доступны. Непустые реальные completed/cancelled строки пока не предоставлены и не подтверждены. Synthetic tests проверяют раскладку колонок и защиту сезона, но не заменяют эту проверку.
- История «Действия» из player.php не добавляется в playerDetails. team.resources не возвращается; management.resources относятся непосредственно к центрам.
- Публичные fixtures полностью synthetic. Присланные authenticated HTML использованы только в отдельной локальной проверке и не опубликованы: активная тренировка и запланированная смена формы сверены. Старые и новые regression tests проходят (`node regression.test.cjs`), включая все восемь комбинаций depth/club/management и фиксированные шесть запросов при roster из 28 игроков. Полный export установленного расширения в cloud browser по-прежнему не проверен.
