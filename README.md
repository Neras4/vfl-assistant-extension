# VFL Assistant v0.5.7

## Главное
Стартовая страница: `https://vfliga.com/managerzone.php`

Два сценария:
- **Собрать мою команду**
- **Собрать ближайшего соперника**

Настройки:
- количество последних матчей;
- глубина сбора:
  - **Обычный** — базовая страница команды/соперника + N матчей;
  - **Глубокий** — профили и последние N матчей игроков; для своей команды также статистика сезона и контракты.

## Что изменилось по сравнению с v0.4
- Экспорт стал компактнее.
- Полный `bodyText` и полный набор всех таблиц больше не сохраняются.
- Сохраняются:
  - core команды;
  - компактный roster;
  - последние N матчей;
  - при deep scan — компактные данные по игрокам.
- `script`, `style`, `noscript`, чат и панель расширения удаляются до анализа.
- Сбор таблиц теперь идёт из очищенного DOM, поэтому `ws_token` не должен попадать в JSON.

## Deep scan в v0.5.7
- Своя команда: `player.php`, найденные вкладки `player_stats.php` и `player_contracts.php` — обычно три запроса на игрока.
- Соперник: только `player.php` — один запрос на игрока. В `playerDetails` отсутствуют `stats` и `contract`.
- `info.recentMatches`: текущий показанный сезон, самые свежие N строк таблицы «Об игроке». Тот же N ограничивает последние матчи команды. Поля: date, competition, opponent, opponentId, homeAway, score, position, minutes, rating, goals, assists, yellowCards, redCards, playerStrength, matchUrl. Скамейка и неизвестные значения сохраняются как null; пропущенные голы вратаря не становятся забитыми.
- Верхние поля игрока берутся из roster, включая неизвестные fatigue/form. `selectedStats` остаётся отдельно от полной статистики.
- Контракт теперь разделён на `current`, `renewal` и `history`. Вместо прежних плоских полей: `current.salaryPerTour`, `renewal.requestedSalaryPerTour` и `renewal.availableTerm`. Renewal содержит прямой запрос зарплаты, отдельный adjustmentPercent и factors с label/percent. Проценты сохраняют знак; зарплата не рассчитывается. BaseSalaryNextSeason отсутствующий на странице экспортируется как null.
- History содержит только реальные строки страницы; дата окончания current берётся из совпавшей строки подписания, если она есть. Полная карьера и дополнительные страницы матчей не обходятся.
- Normal, данные клуба и `team.resources` не менялись: resources отсутствует.

## Установка
1. Распаковать ZIP.
2. Открыть `chrome://extensions` (или страницу расширений браузера).
3. Включить режим разработчика.
4. `Load unpacked / Загрузить распакованное расширение`.
5. Выбрать папку `vfl-assistant-extension-v0.5.7`.
6. Открыть `https://vfliga.com/managerzone.php`.

## Исправления v0.5.2
- Deep player export теперь нормализован по полям вместо большого текстового `summary`.
- `info`: позиция, возраст, сила, усталость, реальная сила, роль, спецвозможности, полезность/минуты, игровая практика, стиль, лояльность, травматичность, зарплата, стоимость, контракт, серия матчей.

## Исправления v0.5.3

- Authoritative current-state поля берутся из roster: name, country, position, age, strength, fatigue, form, realStrength, specials.
- player.php дополняет только profile-only поля: role, usefulness, gamePractice, style, loyalty, injuryRisk, salaryPerTour, value, contractUntil, playedInRow.

## Исправления v0.5.4
- Исправлены индексы jPlayer: усталость 12, форма 13, направление формы 14. Неизвестные значения экспортируются как null.
- Сбор своей команды отдельно читает текущие показатели из managerzone?sort=300: товарищеская усталость 25% не подменяет текущую. Выбранная на исходной странице статистика сохраняется в players[].stats вместе со scope. Если статистики на исходной странице нет, используется статистика sort=300.
- Добавлены оценка, игры, голы, пасы и карточки из roster/jPlayer. VFL sort=300 на проверенной странице показывает соревновательные матчи; его показатели могут отличаться от итогов player_stats, включающих товарищеские.
- Форма и направление читаются также из title карточки игрока. Profile-поля читаются по ячейкам, пустые значения не захватывают соседний текст.
- player_stats: выбранный сезон из select, итоговая оценка из отдельной ячейки, total и tournaments без повторного суммирования командных подстрок. Минуты сезона берутся из player.php.
- Контракт: предложение зарплаты хранится с числом следующих сезонов; предложение на три сезона не называется зарплатой на один следующий сезон.
- Исправлено чтение отсоединённого DOM: ссылки вкладок и тексты fetched pages не зависят от innerText.
- Выбор соперника сначала ищет ближайший будущий матч со ссылкой на состав. Параллельный запуск сбора блокируется.

## Данные клуба в v0.5.6
- Один выключенный по умолчанию чекбокс «Данные клуба»: финансы, история сделок и командная статистика. Только для кнопки своей команды, независимо от normal/deep; deep по-прежнему добавляет только playerDetails.
- Own export всегда содержит `clubDataIncluded: true/false`. При true добавляются отдельные `finances`, `deals`, `teamStatistics`. В opponent export этих полей нет даже при включённом чекбоксе.
- Источники: managerzone `pm=6`, `pm=4`, `pm=3`. Проверяется ID активной команды на каждой странице. Ошибка загрузки или смена команды прерывает сбор, чтобы не экспортировать смешанные данные.
- `finances`: выбранный сезон и ledger `date`, `description`, `balanceBefore`, `income`, `expense`, `balanceAfter`; отсутствующие суммы — null, расход хранится положительным числом. Категория не угадывается, текущий баланс не дублируется. Относительные даты сохраняются как показаны на странице.
- `deals`: выбранный сезон и завершённые transactions с типом, исходным разделом, датой, игроком, суммой и контрагентом. Подтверждены разделы покупок и продаж на трансферном рынке; неудачные попытки и выпускники спортшколы исключены. Блоки аренды/обмена на проверенной странице не представлены, их mapping не угадывается. Суммы с «к» переводятся в единицы игровой валюты. Неподтверждённая структура блока не парсится по предположению.
- `teamStatistics.metrics`: аналитические значения и рейтинги league/continent/country/division; знак изменения читается из title. Для Vs/s11/s14/s17, вместимости и финансов сохраняются только Ranking-поля. Core не перезаписывается. История тренеров не собирается.
- Данные относятся к показанному сезону/страницам. Архивы и все sort-фильтры не обходятся. Новых зависимостей и management collectors нет.
- `team.resources` удалён: уведомления не отражают остаток ресурсов при занятых слотах.
- Проверены DOM и контрольные значения трёх реальных клубных страниц, а также synthetic tests всех комбинаций own/opponent и normal/deep. Полная проверка кнопок и скачанных JSON в установленном расширении остаётся незавершённой: в доступной браузерной сессии расширение отсутствует.

## Исправления v0.5.5
- ID для deep scan берутся из полного `roster.players` в стабильном порядке без дублей. Единичная ссылка `player.php` больше не обрезает состав.
- Статистика выбранного фильтра: `roster.players[].selectedStats` и `playerDetails[].selectedStats`. Полная статистика остаётся в `playerDetails[].stats`; при merge они не заменяют друг друга.
- Восстановлены счётчики скаут-центра, включая «Есть … изучений стилей» и нулевые значения. Отсутствующие значения остаются `null`.
- Из названий турниров удаляется только отдельный служебный счётчик VFL. `-` означает 0 для событий и игр, но неизвестную среднюю оценку — `null`. Итог берётся из total row.
- Скрытые усталость и форма соперника остаются `null`; mapping текущих показателей сохранён.

### Проверка
Регрессионные проверки: `node regression.test.cjs` (без зависимостей и сетевых запросов). Публичные тесты используют вымышленные данные. Проверены парсеры и сценарии own/opponent normal/deep с synthetic documents и подменённым транспортом. DOM и значения повторно сверены в авторизованном браузере. Полный запуск установленного расширения и скачивание JSON в этой браузерной сессии не проверены.

### Обновление
Распакуйте архив, замените папку установленного расширения, нажмите «Обновить» на chrome://extensions и обновите вкладку VFL. Проверьте номер v0.5.7 на панели.

### Проверка v0.5.7
Перед изменением проверены авторизованные страницы профиля, статистики и контракта своего игрока, публичный профиль текущего соперника и обозначение жёлтой карточки. Synthetic tests проверяют три запроса own, 28 запросов opponent, отсутствие deep requests в normal, лимит N, неизвестные значения, факторы и историю. Все проверки `node regression.test.cjs` проходят. Полные Own Deep / Opponent Deep JSON из установленного расширения пока не проверены: в доступном cloud browser расширение не установлено.
